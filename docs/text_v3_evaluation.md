# Text-only PE evaluation v3

本协议只比较原始提示词及两份 PE 文字，不读取生成视频，不需要人工盲评。
它是新增的自定义协议，旧 PEBench 24 项、历史运行和模型自报分数保持原样。
新旧总分不具备直接可比性，不将历史分数重新映射成 v3。

## 评价流程

1. 仅向裁判提供原始提示词、时长和原文需求辅助清单，冻结原子要求及 24 个细项的适用性。
   需求引用必须是原文连续子串。每个需求只归属一个 SF 细项。
   明确禁令、精确台词/文字、主体数量、关键事件及约束为 critical（权重 3），其他为 normal（权重 1）。
2. 同时提供匿名候选 A、B，分别调用 SF、IC、DC。请求中不发送方法名、文件名或视频。
3. 交换 A/B 顺序，再评分一次。模型不输出总分或胜负，程序从逐项结果计算。
4. 顺序导致胜负不一致、某维度分数变化超过 5 分或严重违例判断不一致时，自动增加一轮正反顺序复核。
   复核后仍不稳定的样本标为 unresolved。完整样本都输出基于正反顺序总分均值的点估计比较；同时单独报告稳定子集结果与 unresolved 数量，不把点估计解释为确定胜负。
5. 所有请求、原始响应、用量、原文计划、候选哈希、评分规则和复核结果写入独立运行目录。
   成功请求可断点复用。更换候选、范围、裁判或协议需新 run ID。

## SF：原始要求保留

逐需求判定 preserved / weakened / omitted / contradicted，分值依次为 1 / 0.75 / 0 / 0。
SF = 100 × 加权满足分之和 / 要求权重之和。
兼容补充不得因为“原文未要求”被判为偏离。遗漏禁令与明确写入禁用内容是不同决策，均需说明损失/影响。
除遗漏允许候选引用为空外，所有判定都必须引用真实的 PE 连续子串。候选文字被程序分段并编号，模型选择片段 ID，程序回填精确引用，避免改写证据。

## IC：文本内部一致性

保留 SAC、ANL、TSC、SPC、PL、AVS。适用项 none / minor / major 的分值为 1 / 0.75 / 0。
IC = 100 × 适用项分值平均。
扣分必须给出两段不同且真实的 PE 引用，具体冲突类别、问题和影响。
只遗漏或违背原始要求归 SF，不能再当成 IC 内部矛盾重复扣分。IC 请求不发送原文正文或需求清单，只发送候选及冻结的适用项，避免将原文与候选差异混入内部一致性判断。
视觉描述中的风、门、撞击不自动意味着声音；精确时间和合理细化也不是矛盾。

## DC：正向设计质量

保留 STC、CDS、ETD、LCS、NDE、CIF、SDI、SPS、VSS，改为适用项 0–4 整数评级。
DC = 25 × 适用项评级平均。

| 评级 | 锚点 |
|---:|---|
| 0 | 缺少关键设计或不可执行 |
| 1 | 空泛、缺少可执行信息 |
| 2 | 基本明确，仍存在重要歧义 |
| 3 | 具体、相关、自洽 |
| 4 | 要素协调、解决关键歧义、适合原始任务 |

CIF 分类为 restatement / useful_detail / padding / conflict。useful_detail 必须指出解决的原文歧义及作用。
以空泛堆砌为主的设计不能超过 2 分，冲突性设计不能超过 1 分。少量套话不使其他可执行设计整体失效。复述已充分明确的原文可以获得高分，不强制增加内容。
每个适用项必须有真实候选引用与实质理由。非适用项不计入分母。
单镜头不强求剪辑，静态展示不强求剧情，未要求音频不强求配乐，未给时长不强求秒级分配，极简风格不强求写实材质。

## 确定性汇总

总体分 = 0.20 SF + 0.20 IC + 0.60 DC。
出现 critical 要求被遗漏/违背，或 IC major 内部矛盾，总分上限 69。
初始权重与上限是明确版本化的方案参数，不是论文公式，也不根据某个方法的输赢动态修改。
SF/IC 违例统计与 DC 平均评级分别展示；不再用 DC pass rate 表达创作质量。
比较分差绝对值不超过 1 分记为平局。
全量点估计偏好得分 = 100 ×（胜场 + 0.5 × 平局）/ 完整配对样本数。稳定子集偏好得分另行报告；两者均与绝对质量分分开展示。

## 使用方法

从项目根目录执行：

```bash
# 验证现有 159 条输入；不调用模型
python3 -m pebench_eval validate --config pe_data/aa_t2v_159/config_text_v3.yaml

# 小范围真实集成检查，请使用独立 run ID
python3 -m pebench_eval evaluate --config pe_data/aa_t2v_159/config_text_v3.yaml --limit 3 --run-id text-v3-pilot

# 七组受控文本变体的自动校准；调用真实裁判，不涉及视频或人工
python3 -m pebench_eval rubric-check --config pe_data/aa_t2v_159/config_text_v3.yaml --run-id text-v3-calibration

# 准备开始独立完整重评时使用
python3 -m pebench_eval evaluate --config pe_data/aa_t2v_159/config_text_v3.yaml

# 重新汇总时自动按运行中保存的协议选择报告逻辑
python3 -m pebench_eval summarize --run-dir pe_data/aa_t2v_159/runs/aa-t2v-159-text-v3-20261116
```

需求不超过 8 条的 case 需要 1 次原文计划 + 6 次维度评审。
较长 SF 评审分批后，N 条需求的初始请求数为 1 + 4 + 2 × ceil(N/8)；实际调用会因缓存减少。
已有原文事实提取可继续作为辅助，但不是这个新原文计划的替代。
每个需要复核的 case 增加 4 + 2 × ceil(N/8) 次评审，格式修复可能额外请求。
`--no-resume` 会重做候选评审，原文计划仍冻结复用。
当前 text-v3 只接受无素材的 T2V case，每例必须有同一对方法的两个候选；I2V/R2V 保持 legacy。

## 自动校准与局限

受控检查涵盖相同文本、等义改写、兼容细化、空泛堆砌、主体数量错误、禁止音乐冲突、事件顺序颠倒。
模型输出 `calibration.json` / `calibration.md`，任一失败或未决使命令非零退出。
该检查能验证明确文本规则和顺序稳定性，不能证明裁判与视频或人类偏好一致。
不保证某一方法胜出，真实的官方 PE 偏离和线上 PE 偏离使用同一标准。

## 格式可靠性修复（2026-11-17）

此次只修复请求协议、校验和断点机制，不调整维度权重、评级锚点、69 分上限、顺序复核或未决规则。
旧完整运行在停止时保存了 5 个完整案例、63 个失败记录、30 份有效计划和 111 个有效维度检查点。

- 计划提取分开提供九个 SF 分类和十五个 IC/DC 适用性定义，避免把 VSS、PL、TSC、AVS 等分类写到需求上。
  SF 适用性由实际需求映射生成，不再要求模型重复判断。原子需求、原文证据和 critical/normal 权重仍由原文计划确定。
- 分类错误单独请求 source-only 分类修复，只允许改动错误需求的 criterion；其 ID、原文引用、含义、权重均冻结。
  不按旧代码硬映射到某个 SF 类别，不默认判定需求已满足。
- IC/DC 请求仅要求适用项。程序先按冻结计划生成 N/A 条目，再校验适用项。
  即使模型对 N/A 返回 rating、severity 或无效引用，该项也排除于评分；不会改变其适用性或分母。
- SF 允许一个或多个片段 ID；每一个 ID 都必须真实存在，所有引用均保留。未知 ID 仍报错。
- 缺项或无效证据按条目局部修复，已通过条目保持原判定；适用项缺分、无证据、无效冲突和违规高分继续严格拒绝。
  新的 SF 长需求评审每批最多 8 条，分批保存；全部需求完成后才汇总 SF，分批不改变权重。
- 成功缓存、未完成的有效条目、每次原始响应、校验反馈和修复结果均保存。重试可从 `.pending.json` 继续。
  `progress.json` 与日志实时显示完整案例数和错误数；完整评分可标记为 unresolved；这只是顺序稳定性标记，不再从全量点估计比较中排除。
- 每次修改提示/协议后使用新 run ID，历史目录保持原样。跨格式导入必须显式指定来源，校验原文、候选、裁判、评分规则、缓存签名和已审核的协议版本。
  只导入可验证的计划与评审检查点；不直接复制最终总分，所有汇总在新运行重新计算。

断点导入可同时使用旧完整运行和后续试跑，后者提供更新的检查点：
